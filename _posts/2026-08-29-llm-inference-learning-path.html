01

Foundations of LLM inference

Every LLM call follows this path. Get the vocabulary and the request lifecycle down before anything else.

Tokenization Forward pass Autoregressive generation Prefill & decode KV cache TTFT & ITL Throughput vs latency
01·Atheaiengineer.substack.com

What is Inference?

Paolo Perrone. Why reading is fast and writing is slow: inference splits into a parallel prefill (the whole prompt in one pass) and a serial decode (one token at a time), and nearly every cost, latency, and KV-cache question traces back to that difference.
01·Btheaiengineer.substack.com

Why is Inference Slow and Expensive?

Paolo Perrone. The economics: decode is bound by memory bandwidth, not compute (the “memory wall”), which is why output tokens cost several times more than input, why a faster GPU alone doesn’t help, and why the KV cache makes long conversations more expensive.
02

Basic transformer concepts

You don’t need to become a transformer researcher — but you should understand the computations inference engines are optimizing.

Transformer block Embeddings Self-attention QKV vectors
02·Abbycroft.net/llm

LLM Visualization

Brendan Bycroft. An interactive 3D walkthrough of a GPT-style model running a single-token inference. Rotate and zoom through embeddings, self-attention, the QKV projections, and the feed-forward layers, right down to individual multiply-adds. Best on desktop.
03

GPU & hardware fundamentals

Most inference bottlenecks are hardware bottlenecks. Understanding the GPU changes how you reason about performance.

GPU architecture Streaming Multiprocessors HBM vs SRAM Memory bandwidth FLOPS Compute-bound vs memory-bound
03·Atheaiengineer.substack.com

What is a GPU?

Paolo Perrone. The chip’s internals for AI: streaming multiprocessors, CUDA cores, tensor cores, and HBM — and why memory bandwidth and VRAM capacity matter more than raw TFLOPS for most inference workloads.
03·Btheaiengineer.substack.com

Why Does AI Need a GPU?

Paolo Perrone. The architectural argument: a neural net is billions of independent multiply-adds, the embarrassingly parallel work thousands of simple GPU cores do at once and a few big CPU cores cannot — plus the cases where a CPU is still the right call.
03·Ctheaiengineer.substack.com

H100 vs H200 vs B200

Paolo Perrone. A buyer’s framework across NVIDIA’s three current datacenter GPUs, decided in priority order by memory capacity, bandwidth, compute, and NVLink: H100 for $/token, H200 for bandwidth-bound decode, B200 for FP4 and rack scale.
03·Dtheaiengineer.substack.com

Why Your Multi-GPU Training Job Keeps Dying

Paolo Perrone. The four ways a small multi-GPU run kills itself — NCCL sync timeouts, one straggler GPU, uneven per-rank memory, un-resumable checkpoints — and the per-rank logging that names which one before you need it. (Training-side, but the same GPU/collective mechanics.)
03·Ehorace.io/brrr_intro.html

Making Deep Learning Go Brrrr From First Principles

Horace He (2022). Decomposes deep-learning runtime into three regimes — compute, memory bandwidth, and overhead — and shows how to tell which one is throttling you, and therefore which optimizations will actually help. The canonical grounding for “compute-bound vs memory-bound.”
04

Inference optimization techniques

How modern inference systems actually get fast — the techniques the engines in stage 5 are built around.

Quantization PagedAttention FlashAttention Chunked prefill Speculative decoding Prompt caching Continuous batching
04·Atheaiengineer.substack.com

What is Quantization?

Paolo Perrone. Lossy compression for model weights — the “JPEG trick” that drops a 70B model from ~140 GB to ~35 GB. Covers the FP16→INT4/NF4 mechanics, PTQ vs QAT, why 4-bit keeps ~99% of quality, and where it degrades (small models, math and reasoning).
04·Btheaiengineer.substack.com

Quantization in Practice: GPTQ vs AWQ vs GGUF

Paolo Perrone. The practical format pick, with the punchline that the kernel (Marlin) matters more than the format: AWQ for vLLM on NVIDIA, GGUF Q4_K_M for CPU/Apple, GPTQ if you’re already shipping it. Same weights can run 10x apart on the right vs wrong kernel.
05

Inference engines

Different engines for different workloads. Match the tool to the shape of the traffic.

vLLM — high-throughput SGLang — shared context llama.cpp — CPU / edge TensorRT-LLM — max NVIDIA
05·Atheaiengineer.substack.com

vLLM vs Ollama vs SGLang vs TensorRT-LLM

Paolo Perrone. Head-to-head on the four serving engines: Ollama for local dev, vLLM as the production default (PagedAttention), SGLang when requests share context (RadixAttention), TensorRT-LLM for max NVIDIA throughput — with a decision tree and the note that TGI is now maintenance-mode.
05·Btheaiengineer.substack.com

Should You Self-Host Inference?

Paolo Perrone. The economics of hosted API vs managed deployment vs full self-hosting, decided in veto order (sovereignty, people, volume, model access). Breakeven sits near ~2M tokens/day, the MLOps salary dwarfs the GPU, and most teams land on a hybrid.
05·Ctheaiengineer.substack.com

What Breaks When You Self-Host an LLM

Paolo Perrone. The four undocumented handoffs that break a self-hosted stack — an API layer silently dropping a field, a patch-release import break, a monitoring bridge missing the KV-cache metric, and the engine rewinding a request under your own state — none of which the engine benchmark tests.
05·Daleksagordic.com/blog/vllm

Inside vLLM: Anatomy of a High-Throughput LLM Inference System

Aleksa Gordić (Aug 2025). An inverse-pyramid deep dive into vLLM’s V1 engine: the scheduler, PagedAttention, continuous batching, chunked prefill, prefix caching, guided and speculative decoding, disaggregated prefill/decode, multi-GPU/multi-node scaling, the serving layer, and benchmarking with the roofline model. Ties stages 4 and 5 together.
